Tab 1
Overview
6 KPI cards showing total organic revenue, sessions, orders, and efficiency metrics — plus a top 10 revenue pages snapshot
GA4 — Daily (2-day lag) Measured — not estimated

This is the first tab you see when you open the dashboard. It gives a single-screen snapshot of how much revenue organic search is generating for ledsone.co.uk — you should be able to answer "how much money is organic search making us?" in 30 seconds from this tab alone.

All numbers come from GA4 ecommerce tracking — this is real, measured revenue attributed to organic sessions by Google Analytics. It is not an estimate and it is not from SEMrush models.

The 6 KPI cards — what each one means
CardWhat it showsWhy it matters
Total Organic RevenueSum of all purchase_revenue from organic search sessions in the latest snapshot period (approximately 90 days rolling)The headline number — how much money Google organic is driving
Organic SessionsTotal number of sessions where the user arrived via organic searchThe volume input — sessions × conversion rate = orders
Total OrdersNumber of eCommerce purchases completed by organic sessionsConversion volume — separate from revenue to catch high-order-count, low-value vs low-order, high-value pages
Revenue / SessionTotal revenue ÷ total sessionsThe efficiency metric — a higher Rev/Session means organic traffic is landing on the right pages. Target: above £1.00
Avg Order Value (AOV)Total revenue ÷ total ordersBasket size from organic buyers. Useful for comparing organic vs paid AOV
Pages with RevenueCount of distinct landing pages that generated at least £0.01 revenue in the periodBreadth of revenue — are 5 pages doing all the work, or is revenue spread across hundreds of pages?
Top 10 pages by revenue

Below the KPI cards you see the top 10 highest-revenue landing pages for the current snapshot period. Each row shows the page URL, page type (Home / Product / Collection / Content), sessions, orders, revenue with a proportional bar, average order value, and revenue per session.

The green revenue bar in each row is proportional to the top page — the page with the most revenue gets the widest bar. This makes it visually instant to see how revenue is concentrated.

The Rev/Session column (teal) is often more useful than raw revenue — a page with 50 sessions and £500 revenue (Rev/Session = £10.00) is more efficient than a page with 5,000 sessions and £1,000 revenue (Rev/Session = £0.20).

Technical details — Overview API

Endpoint: GET /api/organic-revenue?type=overview

Queries: google_analytics.organic_landing_page_revenue filtered to run_date = (SELECT MAX(run_date) ...) and session_default_channel_group = 'Organic Search'. Returns 3 parallel queries: totals (SUM aggregates), top10 (per-URL, ordered by SUM(purchase_revenue) DESC, LIMIT 10), meta (MAX run_date, MAX date_end, MIN date_start). Page type classification via SQL CASE on landing_page URL patterns. Rev/session and AOV computed server-side.

DB ColumnUsed as
purchase_revenueRevenue in GBP
ecommerce_purchasesOrder count
sessionsSession count
run_dateSnapshot date (used as filter key)
session_default_channel_groupChannel filter — 'Organic Search'

Date range filter

The date range bar (shown only when this tab is active) controls which rows appear. It filters by date_end — the end of the reporting window for each GA4 run. Preset buttons: 30d, 90d (default), 6m, 1y, All. You can also enter custom dates manually.

The Overview, By Page Type, and Trend tabs always show the latest snapshot — only this tab responds to the date range filter.

CSV Export

The ↓ Export CSV button in the top right exports all currently filtered rows (up to 1,000). The file includes: landing_page, page_type, sessions, active_users, orders, revenue_gbp, avg_order_value, rev_per_session. File is named with today's date for easy archiving.

⚠️ Zero-revenue rows: Blog posts and informational pages often show 0 orders and £0 revenue — this is expected. These pages attract informational traffic that rarely converts directly. Use the Revenue > 0 only filter to hide them and focus on pages that generate sales.
Technical details — By Landing Page API

Endpoint: GET /api/organic-revenue?type=by-page&from=YYYY-MM-DD&to=YYYY-MM-DD

Queries google_analytics.organic_landing_page_revenue filtered to run_date = MAX(run_date) and date_end BETWEEN $1 AND $2. Groups by landing_page, returns up to 1,000 rows ordered by SUM(purchase_revenue) DESC. Page type classification via SQL CASE expression. Sorting, searching, and type filtering all happen client-side in the browser after the initial fetch — no second API call on filter changes.

Revenue broken down by page category — Home, Product, Collection, Content, and Other — with share percentages and a donut chart
GA4 — Latest Snapshot

This tab answers the question: "What type of page is driving organic revenue?" It groups every landing page into one of 5 buckets based on the URL pattern, then shows how revenue, sessions, and orders are distributed across those buckets.

The 5 page type buckets
TypeURL PatternColourWhat it means
HomeExactly /BlueSessions that landed on the homepage. Usually brand searches or generic "LED lights UK"-style queries.
Product/products/...GreenIndividual product pages. High-intent — these visitors are usually ready to buy.
Collection/collections/...PurpleCategory / collection pages. Mid-funnel — browsing a range of products.
Content/blogs/... or /pages/...AmberBlog posts and guide pages. Mostly informational traffic — lower direct conversion but builds brand and assists later purchases.
OtherEverything elseGreySearch pages, account pages, misc URLs. Usually very low revenue.
Cards and the share bar

Each page type has a card showing: total revenue, share % of all organic revenue, sessions, orders, pages in the type, pages within that type that have revenue, average order value, and revenue per session. The coloured bar below the revenue figure shows that type's proportion visually.

How to use this tab

If Collections drive the most revenue — prioritise improving collection page copy, internal linking from blog posts to collections, and ranking more collection pages higher in GSC.

If Products have high AOV but low sessions — there is revenue upside from driving more organic traffic to product pages (via keyword improvements, better internal linking from collections).

If Content has very low Rev/Session but high sessions — this is typical. Content pages rarely convert directly. Consider adding product recommendation modules or internal links within blog posts to product/collection pages.

💡 Donut chart: The chart at the bottom of this tab shows revenue share by page type visually. Hover over each segment to see the exact revenue and percentage.
Technical details — By Page Type API

Endpoint: GET /api/organic-revenue?type=by-type

Queries google_analytics.organic_landing_page_revenue filtered to run_date = MAX(run_date) and session_default_channel_group = 'Organic Search'. Groups by the SQL CASE expression for page_type. Returns SUM(purchase_revenue), SUM(sessions), SUM(ecommerce_purchases), COUNT(DISTINCT landing_page), COUNT(DISTINCT CASE WHEN purchase_revenue > 0 THEN landing_page END), plus computed rev_per_session and avg_order_value. Ordered by SUM(purchase_revenue) DESC.

Page type SQL: CASE WHEN landing_page = '/' THEN 'Home' WHEN landing_page LIKE '/products/%' THEN 'Product' WHEN landing_page LIKE '/collections/%' THEN 'Collection' WHEN landing_page LIKE '/blogs/%' OR landing_page LIKE '/pages/%' THEN 'Content' ELSE 'Other' END

Tab 4
Revenue Trend
Monthly revenue bar chart with trend line, plus sessions and orders charts — and a last-12-months MoM table
GA4 — Monthly Aggregation

This tab answers: "Is organic revenue growing month on month?" It aggregates the GA4 data by calendar month (using run_date) to show the trend over time. This is the clearest view of whether organic search is becoming more or less valuable to the business.

The 3 charts
ChartWhat it showsWhat to look for
Monthly Organic RevenueGreen bars (monthly revenue) with a blue trend line overlayIs the trend line going up? Month-to-month variation is normal — the trend line smooths it out. A consistently rising line = organic is growing. A flat or falling line = a problem.
Monthly SessionsTeal line — total organic sessions per monthCompare with revenue chart. If sessions are rising but revenue is flat, conversion is weakening. If revenue rises faster than sessions, AOV or conversion rate improved.
Monthly OrdersPurple line — total eCommerce purchases per monthIf orders drop but revenue stays flat, AOV increased (bigger baskets). If orders rise but revenue drops, basket size shrank.
Month-on-Month table — last 12 months

Below the charts is a table showing the last 12 months with MoM % change for revenue (green = growth, red = decline). Use this to identify which specific months had drops and correlate with business events — a sale, a Google algorithm update, a product launch, a change in paid spend.

How the monthly aggregation works

The GA4 pipeline writes one snapshot per day to the DB (each snapshot covers an approximately 90-day rolling window). The trend chart groups these snapshots by DATE_TRUNC('month', run_date) — so each point on the chart represents the sum across all daily runs within that calendar month.

This means the most recent month on the chart will usually look lower than previous months because it only has a partial month of daily runs (e.g. if today is Aug 4, only 4 daily runs exist for August). This is not a decline — it is an incomplete month. Compare completed months only for trend decisions.

⚠️ Partial month warning: The current month on the trend chart is always incomplete — it only includes days elapsed so far. Do not compare it to previous full months when assessing MoM performance. Use the prior full month vs the month before it for a fair comparison.
Technical details — Trend API

Endpoint: GET /api/organic-revenue?type=trend

Queries google_analytics.organic_landing_page_revenue filtered to session_default_channel_group = 'Organic Search'. Groups by DATE_TRUNC('month', run_date)::date. Returns month, MAX(run_date), SUM(sessions), SUM(ecommerce_purchases), SUM(purchase_revenue), COUNT(DISTINCT landing_page), COUNT(DISTINCT CASE WHEN purchase_revenue > 0 THEN landing_page END). No date range filter applied — returns all available months. Ordered ASC by month.

Note: because each daily run covers an overlapping 90-day window, the monthly SUM is the sum of all daily snapshot rows within that calendar month — not a deduplicated 30-day revenue figure. This is consistent across all months, so the trend direction is valid even though absolute monthly totals include overlap.

How GA4 attributes revenue to landing pages

GA4 records the landing page — the first URL a user visited in their session. If that session had an organic source (Google, Bing, etc.) and the user completed a purchase before the session ended, GA4 attributes that purchase revenue to that landing page and that channel group.

This means if a user lands on /collections/pendant-lights from Google, browses to /products/xyz, and then purchases — the revenue is attributed to /collections/pendant-lights (the landing page) under Organic Search. This is standard GA4 session attribution and is what makes the By Landing Page tab meaningful.

✅ No Shopify join required: The revenue figures come directly from GA4's own eCommerce tracking — GA4 records the transaction at the moment of purchase and already knows which session and channel it came from. There is no need to join GA4 session data to Shopify order data for this dashboard.
Technical details — API architecture

API file: api/organic-revenue.js — Vercel serverless function, Node.js 24, maxDuration 60s. Single file routing via ?type= parameter. Connects to Ledsone PostgreSQL via process.env.POSTGRES_URL with SSL. Connection per request (no pool — Vercel serverless). Statement timeout: 30s. Four handlers: handleOverview, handleByPage, handleTrend, handleByType. CORS headers: Access-Control-Allow-Origin: *. Cache-Control: no-store to always serve fresh data.

Page type SQL CASE is defined as a constant PAGE_TYPE_SQL and reused across all 4 handlers — single source of truth for classification logic.

Glossary
Plain-English definitions of every term used in the dashboard
AOV — Average Order Value
Total revenue divided by number of orders. A higher AOV means customers are buying more per transaction. Useful for comparing different page types — product pages often have higher AOV than collection pages.
Channel Group
How a user arrived at the site. Organic Search = clicked a non-paid Google/Bing result. This dashboard only shows Organic Search rows — all other channels are excluded.
date_end / date_start
The start and end of the reporting window for each GA4 run. Each daily run covers approximately 90 days. date_end is always the day before the pipeline ran.
eCommerce Purchase
A completed transaction tracked by GA4. This is when a customer clicks "Place Order" and the order is confirmed. Counted per session — one session can have multiple purchases but this is rare.
GA4 — Google Analytics 4
Google's current analytics platform, replacing Universal Analytics. Tracks sessions, events, and eCommerce on ledsone.co.uk. The source of all data in this dashboard.
GA4 Processing Lag
GA4 takes 24–48 hours to finalise session data before it is available via the export API. This is why today's dashboard data is always 1–2 days behind today's date. It is a Google constraint, not a pipeline fault.
Landing Page
The first URL a visitor sees in their session — where they "landed" from organic search. Revenue is attributed to this URL regardless of where on the site the purchase eventually happened.
Organic Search
Traffic that arrived via unpaid (non-advertised) search results on Google, Bing, or other search engines. Google Ads traffic is NOT included — that falls under "Paid Search".
Page Type
A classification applied to each landing page based on its URL pattern: Home (/), Product (/products/…), Collection (/collections/…), Content (/blogs/… or /pages/…), or Other. Applied in the API — not stored in the database.
purchase_revenue
The GA4 database column containing the GBP revenue value for a session. This is the real transaction value passed to GA4 by the Shopify checkout. It is measured data, not an estimate.
Rev/Session
Revenue per Session = total revenue ÷ total sessions for a page. The most useful single efficiency metric for organic landing pages. A page with Rev/Session of £5.00 is 10x more efficient than one with £0.50 — even if the £0.50 page has more raw sessions.
Rolling Window
Each daily GA4 run covers a fixed number of days back from the run date (approximately 90 days). The window "rolls" forward by one day each day. This is why the total figures in Overview are cumulative over a period, not a single day's revenue.
run_date
The date the GA4 pipeline ran and wrote data to the database. The dashboard always shows data from the most recent run_date by default. The Trend tab groups by month using run_date.
Session
A single visit to ledsone.co.uk. A session starts when someone arrives and ends after 30 minutes of inactivity. One person can generate multiple sessions — but each session has one landing page and one channel group.
Zero-Revenue Page
A landing page that had organic sessions but no purchases in the period. Blog posts and guide pages commonly show £0 revenue — they attract informational traffic that does not convert directly. Use the Revenue > 0 filter to hide these.
