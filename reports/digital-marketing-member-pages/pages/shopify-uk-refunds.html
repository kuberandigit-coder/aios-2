Source: Shopify UK Admin API (ledsone.myshopify.com, API version reused from the existing api/salesuk.js integration — no second Shopify auth system created). Orders queried by updated_at over a wide window, then precisely filtered to refunds whose own createdAt falls in the last 60 days (so refunds on older orders aren't missed).
Grain: one row = one refund × one refunded line item. A refund with no line item (e.g. shipping-only) still gets one summary row, flagged as such, so it isn't silently dropped.
Refund Amount: Shopify's own RefundLineItem.subtotalSet (the line's actual refunded amount as recorded by Shopify) — not recalculated from price × quantity.
Refund Reason: Shopify's Admin API has no structured "reason" field on a Refund — the actual text Shopify stores when a refund is created is the Refund.note field. That is what is shown here. If empty, shown as "Not Provided" — never inferred from product, order notes, or anything else.
Pagination: full hasNextPage/endCursor pagination, no page limit other than a high safety cap.
Known limitations
1. Shopify's Refund object doesn't have a dedicated reason enum in this API version — note is the closest real field and is what's shown; if staff don't type a note when refunding, it will show "Not Provided" (this is expected and accurate, not a bug).
2. Read-only — no refunds, orders, or products are created/modified by this page.
3. First load serves fast; the "Refresh (live)" button re-queries Shopify directly and can take longer for a full 60-day scan.
